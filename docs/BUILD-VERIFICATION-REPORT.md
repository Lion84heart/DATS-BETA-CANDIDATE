# Build Verification Report — DATS-BETA-CANDIDATE v1.0.0-beta Build Fix #001 Date: 2026-08-17 Status: RESOLVED Severity: HIGH (deployment-blocking) Classification: Missing Runtime Dependency — Dependency Declaration Gap Reporter: Automated build verification system Fix Engineer: Kimi orchestrator with sub-agents ## 1. Problem Summary The DATS Beta deployment successfully built its Docker image and started the container, but the application crashed during startup with a `ModuleNotFoundError: No module named 'scipy'`. The failure occurred during import of `trading.ab_testing`, which performs statistical A/B testing using Welch's t-test from `scipy.stats`. ## 2. Root Cause Analysis ### 2.1 Primary Root Cause: `scipy` omitted from dependency declaration The module `src/trading/ab_testing.py` contains a top-level import: ```python from scipy import stats ``` However, `scipy` was **not listed** in the `dependencies` array of `pyproject.toml`. When `pip install -e .` ran during the Docker build, `scipy` was never installed into the container. On import, Python raised `ModuleNotFoundError`. ### 2.2 Secondary Finding: `python-jose` missing (non-fatal but degrading) The authentication module `src/api/auth.py` imports `jose` (provided by the `python-jose` package) inside a `try/except` block. When the package is missing, authentication falls back to a simple colon-delimited token format instead of proper JWT. This is a **security degradation** in production. ### 2.3 Tertiary Finding: `textual` missing (TUI non-functional) The TUI application `tui/main.py` requires the `textual` library, which was also absent from `pyproject.toml`. A `pip install` from the project would not install `textual`, rendering the terminal interface non-operational. ### 2.4 Contributing Factor: PYTHONPATH not set in Dockerfile Even after adding `scipy`, the Dockerfile's `CMD [uvicorn, src.api.main:app, ...]` would have failed because internal package imports (e.g., `from trading.ab_testing import ...`) expect `src/` to be on `PYTHONPATH`. The original Dockerfile did not set `PYTHONPATH`. ## 3.
